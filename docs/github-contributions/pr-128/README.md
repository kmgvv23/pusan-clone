## 구현하면서 고민한 점

RAG 구조가 평소 상식과 달라 여러 의문이 들었습니다.
   
- **고민** : RAG는 정확한 대규모 내부 문서를 참조할 때 쓰는 것이라 생각했는데, 이번 과제의 벡터DB에는 사용자가 직접 넣은 소량의 개인 메모만 쌓입니다. 이렇게 적은 데이터로 효용이 있는지, distance 임계치는 어떻게 정하는지, 관련 없는 항목이 뽑혀 할루시네이션이 생기지 않는지 고민했습니다.
- **직접 확인** : "비밀번호 4590"만 저장하고 "현관 도어락 비번 뭐였지?"라고 물으니, 저장한 적 없는 "현관 도어락"을 단정해 답하는 할루시네이션을 재현했습니다. 반면 "이대리 연락처?"나 "내 생일?"은 잘 방어됐는데, 라벨이 명확하면 방어하고 뭉개지면 단정하는 등 결과가 일관되지 않았습니다.
- **대안** : 검색 관련성을 코드로 거르는 threshold가 없어, 프롬프트에 "검색 결과가 없으면 지어내지 말고 저장된 내용만 근거로 삼는다"는 방어를 넣었습니다. 다만 이 방어는 "검색 0건"은 막았지만 "부분적으로만 일치하는" 경우는 강한 문구를 넣어도 막지 못했습니다. 이 경계를 확실히 하려면 distance threshold·re-ranking 같은 코드 단 보완이 필요하다는 것을 한계로 확인했고, 이번 과제 범위(agentic RAG 기초)에서는 프롬프트로 최소 방어만 두었습니다.
- **라우팅 기준** : "일정이 아니면 무조건 메모"로 두면 잡담까지 저장소에 쌓일 것 같아, "사용자가 기억/메모 의도를 밝혔을 때만 참고자료로 저장"하도록 정했습니다.

## 멘토님께 드리는 질문 (개인적으로 궁금한 점)

과제와는 별개로, 요즘 LLM을 일상적으로 쓸 때와 프로젝트를 할 때 공통적으로 드는 큰 의문이 있어 여쭤보고 싶습니다. AI를 활용하는 작업을 할수록 뭔가 모를 찝찝함이 남습니다.

** 1) AI를 활용한 프로젝트에서 **

에이전트나 모델에 입력과 출력이 있을 때,

- **입력** : 우선 입력으로 어떤 자료까지 넘겨줄 것인지, 그리고 어디까지를 rule-base로 처리하고 어디부터는 모델이 직접 판단하도록 놔두는 게 나은지 그 경계가 늘 애매합니다.
- **출력** : 이번 카테캠 과제에서도 그렇듯 출력 형식을 프롬프트로 강제하는데, 정확한 형식이 필요한 것을 "프롬프트"라는 수단으로 제어하는 게 과연 맞는 방식인지 의문이 듭니다.
- 근본적으로 LLM은 기본 개념부터 확률 기반인데, 물론 다양한 tool·harness·skill로 보완은 하지만, 정확한 결과물이 반드시 있어야 하는 상황에서 확률 기반 모델을 쓰는 것 자체가 맞는 것인지 고민이 됩니다.

**2) 일반적인 작업에서**

예를 들어 cowork 같은 걸로 해커톤 주제나 논문 주제를 정한다고 할 때, 제가 많이 아는 상태에서 진행하는 게 가장 좋겠지만, 어쩔 수 없이 AI에 기대어 하는 작업이 늘고 있습니다. 그 과정에서 두 방향 모두 어려움을 느낍니다.

- 제가 원하는 것을 **큰 틀만, 예를 들어 goal 모드처럼 목표만** 던지면, AI가 너무 엉뚱한 작업으로 오랫동안 진행해버립니다.
- 반대로 **특정한 방향으로 유도**하면, 그 답변들이 실제로 유의미한지 아닌지도 모른 채 그 방향으로 계속 이어져 갑니다.

기본 지식이 많으면 이를 적절히 컨트롤할 수 있겠지만, 제가 잘 모르는 영역에서 고난도 작업을 해야 할 때는 오히려 생산성이 잘 안 나오는 것 같습니다. 이건 어쩔 수 없이 감수해야 하는 부분일까요, 아니면 멘토님만의 기준이나 노하우가 있으신지 궁금합니다.

생각해보면 AI 를 쓰든 안쓰든 고난도 작업이라는 사실은 변하지 않습니다.

개인적으로 저는 시간과 노력이 많이 드는 작업을 AI 를 통해 효율적으로 진행하는 것 뿐이지,
어렵고 힘든 일을 AI 를 사용한다고 해서 쉽게 해결되지 않는 것 같습니다.

저는 회사에서 Redis 관련 플랫폼을 운영중에 있습니다.
최근 Redis 신규 버전을 검수하고 배포하는 작업을 진행했습니다.
이를 위해 다음과 같은 업무를 진행했습니다.

1. Redis 신규 버전에 추가된 기능 리서치
2. 추가된 기능 중 중요한 기능들 추리기
3. 중요한 기능들에 대해서 테스트 진행

위 업무 모두 AI 에게 도움을 받았습니다.
그 중 가장 AI 를 활용하여 생산성이 높아진 업무는 1,2번 작업이었으나,
AI 를 활용하여 가장 많이 배울 수 있었던 것은 3번 작업이었습니다.

제가 AI 활용역량이 아직 부족한 것일 수도 있습니다...
그렇지만 결국 이러한 시행착오를 통해 제 나름의 AI 활용법을 익혀가고 있습니다.
